**What changed**

- Added a Phase 5 Rank-PGD strength sweep runner for MSLS and SPED with a 20-condition-per-dataset default grid, expanded into one job per dataset and condition.
- Added `--parallel_runs` for concurrent `rank_eval.py` subprocesses, JSON config support, CLI-over-config precedence, dry-run output, smoke mode, per-dataset/per-condition output directories, manifest writing, result collation, and strongest-setting selection.
- Added `--resume_sweep_dir` and `--force_rerun_completed` so interrupted sweeps can skip valid completed jobs, rerun incomplete jobs, preserve prior attempt logs, and resume safely with a different `--parallel_runs` or `--infer_batch_size`.
- Updated the sweep runner default to SPED-only, `--parallel_runs 1`, and `--execution_mode in_process`.
- Added in-process dataset-pass execution that loads models, builds the dataset, extracts clean descriptors, and caches attack targets once per dataset pass before running pending conditions.
- Kept the older one-subprocess-per-condition scheduler behind `--execution_mode subprocess`.
- Added `--max_dataset_samples` to the sweep runner and `rank_eval.py` for deterministic sampled-gallery query/database caps from `--seed`; omitted caps keep full-dataset behavior.
- Added validation that in-process `--parallel_runs` cannot exceed the number of selected datasets and that sampled galleries are large enough for the strongest configured hard-negative count.
- Added the repository root and vendored `third_party/SuperVLAD` paths at sweep-runner startup so default in-process execution can import `rank_eval.py` and SuperVLAD helpers such as `commons` without a manual `PYTHONPATH`.
- Added a CUDA cache flush before each in-process attack condition to reduce OOM risk from PyTorch reserved-but-unallocated memory.
- Added unit tests for condition generation, the 20-condition cap, dataset-condition job expansion, in-process grouping, config precedence, parallelism validation, deterministic sampling, smoke/query-cap behavior, resume behavior, command generation, summary collation, and selection tie-breaks.
- Updated project documentation and the Sprint 1 task plan to describe the new runner and current validation status.

**Context**

- Phase 5 needs a controlled attack-strength sweep that evaluates MSLS and SPED only, avoids unbounded Cartesian products, and can use parallel execution when hardware resources allow.

**Impact**

- The sweep can be launched or resumed through `scripts/run_rank_pgd_strength_sweep.py`.
- Final full benchmark runs are protected from accidental query caps because `--max_queries` is accepted only with `--smoke`.
- In default in-process mode, the SPED sweep produces 20 condition results through one dataset pass. Explicit MSLS/SPED runs can use at most two concurrent dataset passes.
- The in-process runner can import `rank_eval.py` and the vendored SuperVLAD modules from the repository root.
- Resuming a failed in-process sweep after CUDA OOM can reuse the same sweep directory; lowering `--infer_batch_size` is still recommended when GPU memory is tight.
- Sampled-gallery mode is opt-in through `--max_dataset_samples` and is marked as not full-benchmark comparable.
- Resume is job-level; a dataset-condition reruns if it does not have a valid completed `rank_eval_results.json`.
- The full benchmark sweep has not been run by this change.
