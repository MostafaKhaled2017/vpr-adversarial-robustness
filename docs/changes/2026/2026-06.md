**What changed**

- Replaced the rank evaluator's single `--resume` and `--eval_dataset_name` public interface with unified `--models`, `--model_tags`, and `--datasets` arguments.
- Updated rank evaluation to support one or more datasets and one or more models, with adversarial queries generated from the first listed model and evaluated on all listed models.
- Updated JSON/CSV output rows to include dataset, model, attack reference model, rank displacement, attack success, and runtime-per-query fields.
- Updated `scripts/run_rank_eval.sh` and appended a multi-dataset base/checkpoint `rank_eval.py` example to `commands.bash`.
- Added lightweight tests for model tag resolution, parser arguments, and CSV flattening.
- Added runtime setup of `third_party/SuperVLAD` in `rank_eval.py` so direct repository-root invocation no longer fails with `ModuleNotFoundError: No module named 'parser'`.
- Updated `tests/test_rank_eval_interface.py` so it does not preload the SuperVLAD path before importing `rank_eval.py`.
- Updated rank evaluation output path handling so every run uses a timestamped directory under the requested output parent, for example `test/rank_eval/YYYY-MM-DD_HH-MM-SS/`, while preserving requested report filenames.
- Added output path tests for default and explicit JSON/CSV paths.

**Context**

- Rank evaluation needed the same style of multi-dataset base/checkpoint comparison command used by `perceptual_eval.py`, while avoiding separate `resume`/`base_resume` and `eval_dataset_name`/`datasets` argument families.

**Impact**

- Existing `rank_eval.py --resume ... --eval_dataset_name ...` invocations must be updated to `--models ... --datasets ...`.
- Single-model evaluation remains available through `--models <checkpoint>` and one or more datasets through `--datasets`.
- Base/checkpoint comparison is available through `--models <base> <checkpoint> --model_tags base checkpoint`.
- Explicit `--output_json` and `--output_csv` values now control report filenames and the parent directory used for timestamped runs, not a reusable logging directory.

**Validation**

- `python3 tests/test_rank_eval_interface.py` passed with 9 tests.
- `python3 -m py_compile rank_eval.py perceptual_adv_training/rank_attacks.py perceptual_adv_training/retrieval_metrics.py perceptual_adv_training/targets.py` passed.
- `python3 -m py_compile rank_eval.py tests/test_rank_eval_interface.py` passed.
- `python3 rank_eval.py --help` passed without a manual `PYTHONPATH` export and showed `--datasets`, `--models`, and `--model_tags` without `--resume` or `--eval_dataset_name`.
- `bash -n commands.bash` passed.
- `bash -n scripts/run_rank_eval.sh` passed.
- Full multi-dataset rank evaluation was not run because it would perform full descriptor extraction and attack evaluation.

**Notes**

- The first model in `--models` is the shared attack reference model.

**What changed**

- Added retrieval metric helpers for Recall@K, nearest-positive rank, rank displacement, and attack success rates.

**Context**

- Phase 1 of the next VPR robustness stage requires replacing weak/proxy attacks with retrieval-native attacks that directly optimize positive-vs-hard-negative rank damage.

**Impact**

- Native rank attack evaluation is available without changing existing FGSM or perceptual evaluation baselines.
- Lightweight tests can run without datasets, checkpoints, CUDA, or FAISS.
- Full benchmark results still require running the evaluator on the intended dataset and checkpoint setup.
